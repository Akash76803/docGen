# Phase 4.9 Fix 1 — Combined PDF Download / Open Actions

## Problem
Phase 4.9 generated the combined PDF bytes successfully, but reused the single Engine PDF URL state and exposed no dedicated combined-PDF download/open controls. Users could see the success message but had no obvious way to save the combined result.

## Fix
- Added dedicated `combinedPdfUrl` and `combinedPdfFileName` state.
- Combined generation no longer overwrites the single Engine PDF download state.
- Successful combined generation creates a Blob URL and immediately triggers a browser download.
- Added `Download Combined PDF` action for repeat download/save.
- Added `Open Combined PDF` action for quick verification.
- Blob URLs are revoked when replaced/unmounted to avoid retained browser memory.
- Combined PDF note explains the automatic download behavior.

## Runtime behavior
1. Select document groups.
2. Click `Generate Selected as One PDF`.
3. Combined renderer completes.
4. The generated PDF is downloaded using its resolved filename, e.g. `Combined_Invoices.pdf`.
5. The panel keeps `Download Combined PDF` and `Open Combined PDF` actions available until another combined PDF replaces it.

## Browser/Tauri note
The current dev command uses Vite/browser download semantics. The actual destination follows the browser/WebView download preference: normally the Downloads folder, or a Save As prompt if the environment is configured to ask for a location. The implementation does not silently assume or claim a filesystem path.

## Regression safety
The combined renderer, pagination, selection, numbering, cancellation, and break-safe logic are unchanged. This fix only wires the generated bytes to explicit output actions.
